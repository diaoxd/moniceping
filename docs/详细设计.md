# 股票买卖训练助手详细设计

## 1. 设计目标

本设计将概要设计中的模块落实为可实现的领域对象、接口、数据库表、状态迁移、计算规则和测试用例。所有交易相关逻辑必须可脱离界面运行和测试。

## 2. 模块与目录建议

```text
src/
```

依赖方向只能从UI指向应用层、应用层指向领域层、基础设施实现领域层定义的仓储接口；领域层不能导入UI和具体数据库代码。

## 3. 领域模型

### 3.1 TrainingSession

```text
id: SessionId
status: created | ready | running | paused | finished | abandoned | cancelled
mode: random | specified | blind | naked | trend | volume_price
symbol: Symbol
period: 5m | 1h | 1d | 1w | 1M
basePeriod: 1d
displayPeriod: 1d | 1w | 1M
startIndex: integer
visibleIndex: integer
totalBars: integer
randomSeed: string
config: TrainingConfig
indicatorConfig: IndicatorConfig
version: integer
```

不变量：

- `0 <= startIndex < visibleIndex <= totalBars`。
- `running`状态才能推进、下单或回退。
- 评测未结束且任一持仓数量大于0时禁止回退；是否在重新空仓后恢复回退能力由会话规则决定，默认允许。
- `visibleIndex`始终指向日线交易日；切换周线或月线不得改变训练进度。
- `finished`、`abandoned`和`cancelled`状态禁止产生新订单。
- `version`每次状态提交后递增。

### 3.2 Account

```text
initialCapital: Money
cash: Money
marketValue: Money
equity: Money
realizedProfit: Money
unrealizedProfit: Money
peakEquity: Money
maxDrawdown: Ratio
```

计算公式：

```text
marketValue = sum(position.quantity * latestPrice)
equity = cash + marketValue
unrealizedProfit = marketValue - position.totalCost
returnRate = (equity - initialCapital) / initialCapital
drawdown = (peakEquity - equity) / peakEquity
```

### 3.3 Position

```text
symbol: Symbol
quantity: integer
availableQuantity: integer
averageCost: Money
totalCost: Money
marketValue: Money
unrealizedProfit: Money
```

一期A股规则：交易数量必须为100的整数倍；若启用T+1，买入数量在下一个交易日之前不可卖出。

### 3.4 Order与Fill

```text
Order {
  id, sessionId, symbol, side, type,
  price, quantity, status, rejectReason
}

Fill {
  id, orderId, fillPrice, fillQuantity,
  commission, stampTax, slippage, totalAmount
}
```

`Order`表示用户意图，`Fill`表示实际成交。一个订单可以没有成交，也可以拆分为多笔成交。

### 3.5 IndicatorConfig

```text
displayPeriod: 1d | 1w | 1M
enabledIndicators: string[]
maPeriods: integer[]
```

约束：

- `maPeriods`去重并按升序保存，每个周期必须为正整数，建议范围为1至250。
- 指标以当前显示周期的K线序列为输入。
- 日线按交易日推进；当前未完成的周K或月K每天重新聚合，因此对应指标每天重新计算。
- 任何指标不得读取 `visibleIndex` 之后的数据。

### 3.6 Review、ReviewStep与TradingPattern

```text
Review {
  id, sessionId, selectedFillId, startStep, currentStep,
  summary, createdAt, updatedAt
}

ReviewStep {
  id, reviewId, step, note, decisionAssessment, tags
}

TradingPattern {
  id, userId, name, category, displayPeriod,
  triggerConditions, klineFeatures, indicatorFeatures,
  volumeFeatures, marketContext, invalidationConditions,
  riskNotes, confidence, createdAt, updatedAt
}

PatternEvidence {
  id, patternId, sessionId, fillId, startStep, endStep, note
}
```

`category`限定为 `open_position | add_position | reduce_position | close_position`，分别表示建仓、加仓、减仓和清仓。模式必须至少关联一个历史交易片段作为证据，后续可基于证据计算出现次数、成功率、平均收益和最大回撤。

## 5. 核心接口设计

### 5.1 创建随机训练

`POST /api/training-sessions/random`

请求：

```json
{
  "marketType": "all",
  "period": "1d",
  "adjustType": "pre",
  "barCount": 150,
  "startYear": null,
  "endYear": null,
  "specifiedSymbol": null,
  "initialCapital": "100000.00",
  "randomSeed": null
}
```

响应：

```json
{
  "sessionId": "sess_001",
  "symbol": "159806",
  "period": "1d",
  "totalBars": 150,
  "visibleIndex": 30,
  "randomSeed": "8ef2...",
  "status": "ready"
}
```

### 5.2 获取训练状态

`GET /api/training-sessions/{sessionId}/state`

只返回当前可见K线、账户、持仓、挂单和训练进度，不返回未来K线。

### 5.3 推进训练

`POST /api/training-sessions/{sessionId}/advance`

请求：

```json
{ "steps": 1, "expectedVersion": 12 }
```

服务端校验版本后推进步骤、处理挂单、更新市值并保存快照。

### 5.4 创建订单

`POST /api/training-sessions/{sessionId}/orders`

```json
{
  "symbol": "159806",
  "side": "buy",
  "type": "market",
  "price": "5.31",
  "quantity": 1000,
  "expectedVersion": 12
}
```

返回订单、成交、费用、账户和持仓的最新状态。重复请求使用幂等键，不能重复扣款。

### 5.5 回退

`POST /api/training-sessions/{sessionId}/rollback`

请求：

```json
{ "targetStep": 11, "expectedVersion": 12 }
```

恢复目标步骤快照，并删除该步骤之后的未确认订单和成交记录；历史审计记录保留回退事件。

回退前必须查询当前持仓。评测未结束且存在持仓时返回 `ROLLBACK_BLOCKED_BY_POSITION`，不得修改可见索引、账户、订单或快照。默认规则下，持仓全部卖出后可再次申请回退。

### 5.6 日 K 心得体会

心得体会绑定训练会话、标的、周期和交易日，不能仅存放在浏览器本地。

```text
GET    /api/training-sessions/{sessionId}/insights?symbol=159806&period=1d
GET    /api/training-sessions/{sessionId}/insights/{tradeDate}?symbol=159806&period=1d
PUT    /api/training-sessions/{sessionId}/insights/{tradeDate}?symbol=159806&period=1d
DELETE /api/training-sessions/{sessionId}/insights/{tradeDate}?symbol=159806&period=1d
```

写入请求：

```json
{ "content": "缩小仓位，等待趋势确认" }
```

数据库使用 `(session_id, symbol, period, trade_date)` 唯一约束。内容长度为 1 至 500 个字符；新增与修改使用同一个幂等 `PUT` 接口。

### 5.7 切换显示周期与指标配置

```text
PUT /api/training-sessions/{sessionId}/chart-preferences
GET /api/training-sessions/{sessionId}/bars?displayPeriod=1w
```

```json
{
  "displayPeriod": "1w",
  "enabledIndicators": ["MA"],
  "maPeriods": [5, 10, 30, 60],
  "expectedVersion": 12
}
```

服务端基于当前 `visibleIndex` 以内的日线返回日K、动态周K或动态月K，并返回对应指标值。切换周期只修改显示偏好，不推进训练日期。

### 5.8 创建与逐步浏览复盘

```text
POST /api/training-sessions/{sessionId}/reviews
GET  /api/reviews/{reviewId}/steps/{step}
PUT  /api/reviews/{reviewId}/steps/{step}
PUT  /api/reviews/{reviewId}/summary
```

创建复盘时可传入 `selectedFillId`。服务端据此确定交易前的起始步骤，并允许在保存的快照范围内逐步向前或向后浏览。步骤响应包含当时可见的日/周/月K线、指标配置与结果、账户、持仓、订单、成交和心得体会。

### 5.9 交易模式库

```text
POST /api/trading-patterns
PUT  /api/trading-patterns/{patternId}
GET  /api/trading-patterns?category=add_position
POST /api/trading-patterns/{patternId}/evidence
```

模式创建请求必须包含分类、触发条件、失效条件、适用周期和至少一个历史片段。模式定义与证据分离，修改模式说明不得改写历史快照。

## 6. 行情场景、周期聚合与指标

### 6.1 随机场景算法

```text
1. 根据市场类型过滤股票。
2. 根据周期和复权方式获取行情序列。
3. 根据年份区间过滤可用起点。
4. 要求起点之后至少存在 barCount 根连续有效K线。
5. 使用 seedable PRNG 选择股票和起点。
6. 保存 seed、筛选条件、候选数量、最终选择。
7. 将 visibleIndex 设置为初始揭示位置，例如 30。
```

数据不足时返回 `INSUFFICIENT_MARKET_DATA`，不能静默降低K线数量。

### 6.2 动态周K与月K聚合

所有训练进度以日线交易日为基准。聚合输入只能取 `timestamp <= 当前训练日期` 的日线：

```text
周期K.open   = 周期内第一根可见日K.open
周期K.high   = max(周期内所有可见日K.high)
周期K.low    = min(周期内所有可见日K.low)
周期K.close  = 周期内最后一根可见日K.close
周期K.volume = sum(周期内所有可见日K.volume)
```

周界限由交易日历确定，月界限由交易所当地自然月确定。当前周或当前月未结束时仍返回一根 `isCompleted = false` 的动态K线；每推进一个交易日，该K线重新聚合。停牌日不伪造K线，节假日不参与聚合。

### 6.3 MA计算

```text
MA(N, i) = 最近N根当前显示周期K线的close之和 / N
```

不足N根时默认不输出数值，不用更短窗口代替。日线MA使用日K，周线MA使用聚合周K，月线MA使用聚合月K。当前未完成周期K的收盘价变化时，包含该K线的所有MA同步变化。MA参数由用户配置，例如5、10、30、60，并随训练会话保存。

## 7. 撮合和费用规则

### 7.1 市价买入

```text
成交价 = 当前K线可成交价 + 买入滑点
成交金额 = 成交价 * 数量
手续费 = 成交金额 * 0.002
扣除现金 = 成交金额 + 手续费
```

### 7.2 市价卖出

```text
成交价 = 当前K线可成交价 - 卖出滑点
成交金额 = 成交价 * 数量
手续费 = 成交金额 * 0.002
增加现金 = 成交金额 - 手续费
```

当前导入行情统一使用前复权数据（`adjustType = pre`）。每笔买入和卖出均按成交金额的千分之二收取手续费，手续费保留至分；可买数量计算必须预留该笔手续费。

### 7.3 涨跌停撮合限制

训练会话可以独立设置以下撮合选项，默认均开启：

- `blockBuyAtLimitUp`：达到涨停价时拒绝买入。
- `blockSellAtLimitDown`：达到跌停价时拒绝卖出。

涨跌停价根据昨收价、会话配置的涨跌停比例和最小价格单位计算。限制必须由撮合服务端执行，客户端开关只负责修改设置和展示拒绝原因。

```text
涨停价 = round(昨收价 * (1 + 涨跌停比例), 2)
跌停价 = round(昨收价 * (1 - 涨跌停比例), 2)
```

### 7.4 订单校验顺序

```text
会话状态
→ 版本号
→ 股票和周期
→ 交易时间
→ 数量格式
→ 价格范围
→ 涨跌停与停牌
→ 资金或持仓
→ T+1限制
→ 撮合
```

## 8. 训练步骤与快照

每个训练步骤保存：

```text
sessionId
step
visibleIndex
cash
positions
orders
fills
equity
realizedProfit
unrealizedProfit
peakEquity
maxDrawdown
displayPeriod
indicatorConfig
indicatorValues
actionTaken
marketDataVersion
```

回退必须恢复上述全部内容，不能只修改当前K线索引。历史复盘快照一旦提交即不可覆盖；即使后续指标算法升级，也应依据快照中的数据版本、配置和已计算结果还原当时画面。

## 9. 错误码

| 错误码 | 场景 |
| --- | --- |
| SESSION_NOT_RUNNING | 会话未处于运行状态 |
| SESSION_FINISHED | 训练已结束 |
| VERSION_CONFLICT | 客户端状态版本过期 |
| INVALID_QUANTITY | 数量不是合法交易单位 |
| INSUFFICIENT_CASH | 可用资金不足 |
| INSUFFICIENT_POSITION | 可卖持仓不足 |
| LIMIT_UP_REJECTED | 涨停规则拒单 |
| LIMIT_DOWN_REJECTED | 跌停规则拒单 |
| SUSPENDED_STOCK | 股票停牌 |
| T1_RESTRICTED | T+1限制 |
| INSUFFICIENT_MARKET_DATA | 行情不足以创建训练 |
| DUPLICATE_REQUEST | 幂等键重复 |
| ROLLBACK_BLOCKED_BY_POSITION | 评测未结束且当前存在持仓，禁止回退 |
| INVALID_DISPLAY_PERIOD | 不支持的显示周期 |
| INVALID_INDICATOR_PARAMETER | 指标参数为空、重复、越界或格式错误 |
| REVIEW_STEP_NOT_FOUND | 复盘步骤不存在或超出快照范围 |
| PATTERN_EVIDENCE_REQUIRED | 交易模式没有关联历史片段 |

UI必须将错误码转换为用户可理解的提示，并保留原始错误码用于日志和测试。

### 10.2 集成测试

1. 创建随机训练并读取初始状态。
2. 推进K线后确认只增加一根可见数据。
3. 买入后确认订单、成交、资金流水、持仓和快照一致。
4. 卖出后确认可用持仓和账户余额一致。
5. 持仓时回退返回 `ROLLBACK_BLOCKED_BY_POSITION` 且状态不变，恢复空仓后按默认规则可回退。
6. 同一训练日期切换日、周、月线，不改变 `visibleIndex` 且不返回未来数据。
7. 日线每日推进后，未完成周K、月K及其MA按新数据变化。
8. 到达最后一根K线后确认状态为 `finished` 且订单被拒绝。
9. 相同随机种子创建的两个会话具有相同股票和区间。
10. 从某笔成交创建复盘，逐步读取的行情、指标、持仓和操作与历史快照一致。
11. 从复盘片段创建四类模式并正确保存证据关系。

### 10.4 UI冒烟测试

- 所有训练卡片存在且可点击。
- 随机训练弹窗可以打开、关闭和取消。
- 市场、周期、复权选项可以切换。
- 未完成必要配置时开始按钮显示校验错误。
- 买入、卖出、观望、下一根、回退均有状态变化。
- 有持仓时回退按钮禁用，并能展示服务端拒绝原因。
- 日线、周线、月线切换后日期锚点不变，动态周期K线无跳变或未来数据。
- 指标开关和MA参数增删即时生效，最长参数不会挤压或遮挡图表。
- 交易拒绝时账户数值不改变。
- 复盘上一步、下一步、步骤笔记、整体总结和模式提取均可操作。
- 移动端无横向溢出和按钮遮挡。

### 10.5 测试门槛

- 领域层单元测试通过率100%。
- 核心交易模块覆盖率不低于90%。
- 一期关键流程端到端测试全部通过。
- 无未处理异常、控制台错误和无响应按钮。
- 每次修改交易规则必须执行全量回归测试。

## 11. 日志与诊断

每次训练记录：

- sessionId
- userId
- commandId
- expectedVersion
- 操作类型
- 输入参数摘要
- 结果状态
- 错误码
- 处理耗时

不记录明文密码和不必要的敏感信息。发生状态不一致时，可以依据命令日志和快照重建问题。

## 12. 开发与验收顺序

1. 先实现领域对象和单元测试。
2. 实现随机场景生成器和数据校验。
3. 实现训练会话和快照。
4. 实现订单、撮合、账户和费用。
5. 用集成测试验证交易闭环。
6. 接入工作台界面。
7. 用Playwright验证真实点击流程。
8. 实现逐步复盘、历史快照读取和交易模式库。
9. 最后实现其他训练模式与模式统计。

任何模块只有在“代码、单元测试、集成测试、验收标准”都完成后，才算完成。
