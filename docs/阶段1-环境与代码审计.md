# 阶段1：环境与代码审计

## 审计结论

- 当前分支：`feature/simulation-training`。
- 当前基线：`v0.1.0-ui-baseline`，提交 `a1124e0`。
- 当前形态：原生 HTML/CSS/JavaScript + Node.js HTTP 服务 + `node:sqlite`。
- 当前测试：`node:test`，基线共6个测试。
- 当前挂载目录未发现 RPS/KlineWeb 工程，暂时不能执行其代码级复用审计和联调。

## 与已确认一期规则的主要差距

- 旧演示撮合使用前复权和0.2%佣金，与后复权、0.03%且最低5元的规则不一致。
- 旧演示页面显示真实日期，并允许直接拖动时间轴，不满足随机训练的信息隔离要求。
- 旧演示没有独立的账户、持仓、订单、成交、快照和会话版本领域模型。
- 旧数据库将演示配置直接写入运行库，尚未实现 `market.db`、`app.db`、`test.db` 分离。
- 随机训练创建、单根推进、T+1、回退、结算和复盘接口尚未实现。

## 本阶段实施边界

1. 固定 Node.js 22、npm锁文件和Python 3.12声明。
2. 新代码按 `src/domain`、`src/app`、`src/infrastructure` 分层逐步建立。
3. 先实现可脱离UI和数据库测试的交易领域规则，再接入API和页面。
4. 现有KlineWeb恢复可访问后，先做组件能力与授权审计，不重写现有K线和指标系统。
